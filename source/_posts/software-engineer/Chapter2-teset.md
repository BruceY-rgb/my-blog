## 1. Software Engineering Layers

软件工程的常见层次包括

- `Process`
- `Methods`
- `Tools`
- `Quality Focus`

!!! warning
`Manufacturing`不是软件工程的层次之一
!!!

## 2. Umbrella Activities

`Umbrella Activities`不是只在项目初期使用，而是贯穿整个软件开发过程

## 3. Five Generic Framework Activities

| English Term  | 中文含义    | 说明                         |
| ------------- | ----------- | ---------------------------- |
| Communication | 沟通        | 与客户、用户交流，理解需求   |
| Planning      | 规划        | 制定项目计划、进度、资源安排 |
| Modeling      | 建模        | 分析需求、设计系统结构       |
| Construction  | 构建 / 施工 | 编码和测试                   |
| Deployment    | 部署        | 交付软件，收集反馈           |


## 4. Software Reuse

软件复用可以降低开发成本并提高系统价值

## 5. Essence of Software Engineering Practice

- 理解问题
- 制定计划
- 制定计划
- 检查结果

## 6. Agile Process Models

在敏捷开发中强调，可工作的软件是衡量进度的**主要标准**，但是不是除了程序以外什么都不要

敏捷项目中也可能有

| English Term     | 中文含义     |
| ---------------- | ------------ |
| working software | 可工作的软件 |
| user stories     | 用户故事     |
| backlog          | 待办事项列表 |
| tests            | 测试         |
| design notes     | 设计说明     |
| documentation    | 文档         |
| prototypes       | 原型         |
| release plan     | 发布计划     |


> 知识点：敏捷重视可工作的软件，但是它不是唯一的交付物

## 7. Business Need

大多数软件项目不是为了写代码而写代码，而是为了满足某种业务需求

> 知识点：Most software projects are initiated to satisfy business needs.

## 8. Software Success 软件成功的标准

软件成功不只是满足设计者的目标，更重要的是满足

- 用户需求
- 客户需求
- 业务目标
- 利益相关者期望(`stakeholder expectations`)
- 显示约束

!!! warning
设计者的目标不一定等于用户真正的需求
!!!
